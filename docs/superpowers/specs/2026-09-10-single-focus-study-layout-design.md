# 单焦点纵向学习页设计

## 背景

当前宽屏学习页把题目和回答拆成左右两张卡，并把评分栏固定在整条窗口底部。实际效果是题目区域偏小、答案提前占位、内容与评分距离很远，屏幕下半部分出现与学习无关的大块空白。面试训练的核心不是同时阅读两栏，而是完成一次连续的“回忆 → 核对 → 评价”。

本设计采用成熟记忆产品中更稳定的单焦点模式：Anki 先显示题目，用户主动回忆后再显示答案并评分；Quizlet 用整张卡翻面和顺序浏览；RemNote 只在需要时补充知识上下文。参考资料：

- [Anki Studying](https://docs.ankiweb.net/studying.html)
- [Quizlet Studying with Flashcards](https://help.quizlet.com/hc/en-us/articles/360030988091)
- [RemNote Creating Flashcards](https://help.remnote.com/en/articles/6025481-creating-flashcards)

## 目标与非目标

### 目标

- 让用户在任何屏幕尺寸下都只有一个主要视觉焦点。
- 未翻面时优先完成口述，不提前展示答案结构。
- 翻面后按“30 秒回答 → 深入理解 → 项目怎么讲 / 易错点 → 高频追问”的顺序阅读。
- 长答案可以自然向下滚动，评分始终能在当前阅读流附近找到。
- 保留现有题库、密码、加密、进度调度和三种评分语义。

### 非目标

- 不新增左右并行的笔记阅读器。
- 不改变卡片内容字段、题库数量和复习算法。
- 不引入知识图谱、侧栏目录或云同步。
- 不把评分按钮变成自动评分或答案正确性判断。

## 核心交互模型

### 状态一：主动回忆

页面只显示一个居中的题目流：

1. 顶部进度条、退出本轮和题库标签。
2. 题目卡中的分类、主题、优先级、倒计时和问题。
3. 主按钮“查看回答”。

回答面板不渲染，不占位；题目卡使用适中的最小高度，但不强行铺满视口。

### 状态二：核对答案

点击“查看回答”后，回答接在同一条纵向阅读流中，题目仍保留在顶部，但不再占用大块固定高度：

1. `30 秒回答`直接显示，使用绿色浅底作为当前结论。
2. `深入理解`、`项目怎么讲`、`易错点`和`高频追问`独立折叠，默认全部收起。
3. 高频追问内部继续使用独立可展开行，避免一次打开后出现长墙。
4. 来源路径放在回答末尾，不抢主阅读层级。
5. 评分栏紧跟回答内容；提交后进入下一张卡，并回到流顶部。

题目与回答使用同一宽度和同一外层视觉容器，避免用户感觉从“题目页面”跳到了“另一个答案页面”。实现上可以保留语义清晰的 `article` 与 `section`，但视觉上通过共享边框、间距和背景组成一个 `study-flow`。

## 响应式布局规范

### 手机：320–767px

- `study-flow` 宽度为视口减去 16px～20px 外边距。
- 题目和回答严格单列。
- 评分栏固定在底部，保留安全区和内容底部 padding，不能遮住最后一条追问。
- 评分按钮保持三等分、最小触控高度 52px。
- 翻面后题目卡收紧上下留白，回答从下方连续出现。

### 平板：768–1199px

- 内容单列，最大宽度约 760px～820px，水平居中。
- 顶部导航保持横向；学习页不显示桌面侧栏。
- 评分栏改为内容流中的操作区，不再固定为整条窗口底栏；当答案较长时可使用局部 sticky，但宽度只跟随内容流。
- 题目字号和回答字号略微放大，保证横屏和竖屏都能连续阅读。

### 电脑：1200px 以上

- 取消题目 / 答案左右分栏，内容流最大宽度约 840px～900px。
- 内容从顶部开始布局，左右留白作为阅读呼吸区，不强行填充。
- 题目卡在翻面后变成紧凑的“问题头部”，回答卡紧接其下。
- 评分栏位于回答内容末尾，宽度与阅读流一致；可使用 `position: sticky; bottom: 16px` 保持可见，但不覆盖整条窗口，也不制造底部白色横带。
- 顶部进度条可以占满主内容区，但不改变内容流宽度。

## 视觉层级

由强到弱固定为：

1. 当前问题。
2. 30 秒回答。
3. 深入理解与追问入口。
4. 项目话术、易错点和来源路径。
5. 分类、主题、优先级和技术来源。

题目卡不再使用大面积空白作为“桌面适配”；通过最大阅读宽度、浅色背景和稳定的纵向节奏表达高级感。答案区域的卡片边框、绿色结论块和折叠行保持现有视觉语言，避免重新引入复杂装饰。

## 组件与数据流

### StudyScreen

- 保留 `revealed`、`saving`、`error` 和队列状态。
- 将题目、回答和评分放入一个 `study-flow` 容器。
- 翻面时只切换渲染状态，不修改卡片数据。
- 评分成功后清空回答展开状态、推进队列，并将滚动位置恢复到学习流顶部。

### ProgressiveAnswer

- 不调整卡片字段和 Markdown 解析。
- 30 秒回答继续默认展开。
- 详细区和每条追问继续默认收起，且换卡时重置展开状态。

### RatingDock

- 手机保留固定底栏。
- 平板和桌面改为学习流内的操作区，桌面可局部 sticky。
- 错误提示紧贴评分区显示，不能把评分按钮推到屏幕外。

## 可访问性与交互边界

- 所有折叠区继续使用原生 `details / summary` 或等价的按钮语义。
- 评分、查看回答和追问按钮触控目标不小于 44px。
- `focus-visible` 样式在浅色背景下保持可见。
- 页面切换和换卡不依赖 hover。
- 用户展开长答案后，浏览器滚动位置不被强制跳动；只有进入下一张卡时回到学习流顶部。

## 测试验收

### 单元测试

- 未翻面时回答和评分不出现在 DOM 中。
- 翻面后题目、回答和评分按纵向顺序出现在同一个 `study-flow` 中。
- 评分成功后回答展开状态清空并推进下一张卡。
- 详细区和高频追问默认收起，已有展开交互保持不变。

### 浏览器测试

- 在 320、390、768、1024、1280、1440 宽度下无横向溢出。
- 所有宽度的题目与回答左边界、宽度一致，回答位于题目下方。
- 桌面端评分栏不再横跨整个视口底部；手机端仍固定在底部且不遮挡内容。
- 长答案展开后，滚动、折叠和评分按钮仍可操作。
- Chrome 和 Safari 覆盖首次加载、翻面、展开追问、评分和换卡。

## 验收标准

- 用户打开一张题时，第一眼只看到一个问题焦点。
- 用户翻面后无需寻找右侧区域即可看到 30 秒回答。
- 电脑端不再出现“卡片只占上半屏、评分固定在最下方”的断裂感。
- 长答案的阅读顺序与口述顺序一致：先结论，再深入，再追问。
- 现有加密、进度、离线和发布流程全部保持兼容。
