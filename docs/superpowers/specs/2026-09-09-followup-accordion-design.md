# 高频追问两层折叠展示设计

## 背景

当前回答组件只在“高频追问”外层使用一个 `<details>`。外层打开后，所有追问答案同时渲染并展开；当一张卡有多条长答案时，移动端会出现连续长文本，用户难以按面试官追问顺序练习。

## 目标

- 30 秒回答保持固定可见，保证翻卡后先获得可口述结论。
- 高频追问默认收起；打开后先看到问题列表，不立即展示全部答案。
- 同一时间只展开一个追问，打开下一题时自动收起上一题。
- 学习页和自由浏览页使用同一套组件和行为。
- 切换卡片、退出学习或重新加载组件时，不继承上一张卡的展开状态。
- 键盘、屏幕阅读器和触控操作与现有折叠区保持一致，触控目标至少 44px。
- 搜索仍检索追问问题和答案，折叠只改变展示，不改变数据。

## 非目标

- 不修改卡片内容、追问排序、进度调度或加密格式。
- 不把答案截断成固定高度；长代码和表格继续完整展示并允许横向滚动。
- 不引入弹窗、抽屉或新的路由，避免打断连续刷题。

## 交互设计

回答区域从上到下保持：30 秒回答、深入理解、项目怎么讲、易错点、高频追问。前三类折叠区继续使用现有独立 `<details>`；高频追问增加一层列表。

1. 外层摘要显示“高频追问 · N”，默认关闭。
2. 外层打开后，每个追问显示为一个可聚焦的问题行；问题行显示序号和完整题干，答案保持关闭。
3. 点击或按 Enter/Space 打开某一题时，只显示该题答案；若另一题已打开，先关闭另一题。
4. 答案内部继续使用现有 Markdown 渲染器，允许段落、列表、代码、表格和链接。
5. 关闭外层时记住本次卡片内的题目选择；切换卡片或组件收到新的卡片 ID 时清空活动题目。
6. 在学习页中，评分底栏保持固定，不随答案长度移动；浏览页沿用同样的单题展开规则。

## 组件与状态

`ProgressiveAnswer` 继续负责四类回答区。新增的追问列表组件接收 `followUps`，内部只维护一个 `openFollowUpIndex: number | null`。外层 `<details>` 的原生展开状态不作为业务状态保存；卡片 ID 变化时通过 key 或 effect 重置 `openFollowUpIndex`。

追问问题行使用 `<button>` 或带明确按钮语义的交互元素，答案区域通过 `aria-expanded`、`aria-controls` 与唯一 ID 关联。若使用原生 `<details>`，需要在 React 状态中同步 open 变化，以保证同一时间只有一个追问展开。

## 样式约束

- 问题行保持至少 44px 高度，问题文本允许换行，不使用省略号隐藏题干。
- 展开题使用轻边框和浅背景区分问题与答案，答案正文沿用现有 `.markdown` 字体、行高、代码块和表格规则。
- 移动端先保证单列和可滚动代码块；桌面端不额外拆成多列，避免阅读顺序变化。
- 展开或收起使用短过渡；不依赖高度动画计算，避免长 Markdown 导致布局抖动。

## 验证

- 单元测试：默认没有追问展开；点击一题只打开该题；打开下一题后上一题关闭；切换卡片后无展开状态残留。
- 可访问性测试：问题行可通过 Tab 聚焦，Enter/Space 可操作，`aria-expanded` 与答案可见性同步，触控目标不小于 44px。
- E2E：学习页和浏览页各覆盖一张含多条长追问的卡；验证外层关闭、单题展开、换卡重置和固定评分栏。
- 响应式检查：320px、390px 和桌面宽度下不产生横向页面溢出；代码块允许自身横向滚动。
- 现有生产构建、类型检查、题库 lint 和加密内容不受影响。

## 采用理由

两层折叠保留了“先看结论、再按需深入”的学习节奏，又把长追问拆成一次只处理一个问题的阅读单元。相比固定高度或弹窗，答案不会被截断，学习过程也不会离开当前卡片。
