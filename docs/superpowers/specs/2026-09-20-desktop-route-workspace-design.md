# 大屏路线学习工作台设计

## 背景与目标

路线详情页在大屏上出现两类无效留白：左侧桌面导航区域只显示 Logo 与锁定按钮，路线正文又被固定最大宽度限制；右侧仅在有技术资料时出现面板。目标是在不改变手机和平板学习流程的前提下，把桌面端变成可以持续学习的路线工作台：阶段可定位、资料可就近查看、正文仍保持适合阅读的行宽。

## 已确认的方案

采用方案 A「左侧路线导航 + 中央学习内容 + 右侧上下文资料」。这是现有代码增量最小、信息密度最均衡的方案。方案 B（宽画布双栏）和方案 C（图标侧栏）只保留在本地预览，不进入正式页面。

## 响应式边界

- 手机（宽度小于 768px）：保留现有单列纵向流、底部主导航、移动阶段目录和技术资料抽屉。
- 平板（768px 至 1199px）：保留顶部主导航与单列路线内容；技术资料继续使用浮动入口和抽屉，不强制常驻右栏。
- 桌面（宽度至少 1200px）：启用左侧桌面工作区、中央路线内容和右侧上下文栏。中央正文最大阅读宽度保持约 1000～1120px，不为了填满屏幕而拉长文字行。
- 超宽屏（宽度至少 1600px）：继续使用同一三栏结构，外侧只增加对称留白；不增加第二份重复内容。

## 页面结构

### 左侧桌面工作区

在 `.app-shell` 的第一列形成 248px 左右的固定侧栏：

- 顶部保留品牌标识。
- 主导航改为垂直排列：首页、浏览、路线、设置；当前页面使用现有 `aria-current="page"` 状态和绿色高亮。
- 锁定按钮固定在侧栏底部，保留现有锁定行为和键盘焦点样式。
- 路线详情页将现有阶段导航在桌面端变为侧栏内的垂直索引，显示阶段序号、短标题和已练习状态；点击后仍通过 `#route-<stepId>` 定位正文并更新 `aria-current="step"`。
- 路线列表页不显示阶段索引，只显示主导航，避免把未选择的路线信息混入侧栏。

### 中央学习内容

中央区域承担路线标题、学习目标、阶段导航和时间线卡片：

- `.route-detail-screen` 在桌面端使用可伸缩宽度，不再把整个内容区域锁死为 1280px。
- `.route-flow-column` 设置 `min-width: 0`，并把阶段卡片正文行宽控制在约 76ch，保证大屏仍然易读。
- 现有横向阶段导航在桌面端不再占用中央首屏高度；它保留为窄屏和平板的导航，桌面由左侧垂直阶段索引承担定位。
- 页面滚动、阶段高亮、练习按钮、阶段复述和原有进度全部沿用，不改变学习数据模型。

### 右侧上下文资料

右栏宽度控制在 320～360px，采用 sticky 面板：

- 顶部显示当前阶段名称、阶段目的和 `已练习 / 总卡片`。
- 有技术资料时显示现有“来自小陈空间”的可折叠资料列表，代码块和 Mermaid 样式沿用当前修复后的版本。
- 没有技术资料时不留空白，显示阶段目标、下一阶段过渡和关联卡片数量等轻量上下文。
- 移动端不渲染常驻右栏，继续使用现有浮动“技术资料”按钮和抽屉。

## 组件与数据边界

- `App.tsx`：只负责桌面侧栏的布局容器，不改变视图切换和解锁逻辑。
- `MainNavigation`：继续作为唯一主导航组件；桌面通过 CSS 垂直布局，窄屏保持现有底部或顶部布局。
- `RouteScreen.tsx`：保留路线状态、滚动监听和阶段选择；补充桌面阶段索引和右栏上下文数据，数据来源仍为 `KnowledgeRoute`、题库卡片、进度和 `ReferenceDocument`。
- `app.css`：集中处理三个断点的网格、sticky 行为、阶段索引样式和右栏 fallback，不新增第三方 UI 库。
- 路线阶段点击只改变 hash、焦点和本地 React 状态，不修改 IndexedDB 进度；只有点击练习并评分时才写入原有进度存储。

## 交互与可访问性

- 左侧主导航和阶段索引的每个项目都是原生 `button` 或 `a`，保留 44px 以上触控目标和现有 `:focus-visible` 样式。
- 桌面阶段索引与正文共享 `aria-current="step"`，滚动到阶段时自动同步高亮。
- 右侧资料继续使用 `details/summary`，支持键盘展开和 Escape 关闭移动抽屉。
- 侧栏和右栏使用 sticky 而不是独立滚动容器，避免页面出现三个同时滚动的区域。
- `prefers-reduced-motion` 下不添加新的动画；布局变化不影响阅读顺序。

## 失败与边界处理

- 路线没有阶段卡片时，中央仍显示阶段说明，并禁用练习按钮；右栏显示“等待题库更新”。
- 当前阶段没有技术资料时，右栏显示阶段上下文，不渲染空的资料列表。
- 视口不足以容纳三栏时，在 1200px 断点以下自动回退到现有单列/抽屉布局，不能出现横向滚动。
- 路线阶段数量变化时，侧栏使用数据驱动列表，不写死 7 个阶段。

## 验收标准

- 在 1280px、1440px、1920px 和 2560px 宽度下，左侧不再只有 Logo，右侧不再出现无意义的大块空白。
- 中央正文每行不超过约 76ch，阶段卡片不被拉伸到难以阅读的宽度。
- 桌面点击左侧任一阶段能定位到对应正文；滚动正文时左侧高亮同步。
- 有资料和无资料的阶段都能保持右栏有意义且不遮挡正文。
- 手机 390px、平板 1024px 的截图和现有 E2E 流程不回归：底部导航、移动目录、资料抽屉和练习评分继续可用。
- `npm test`、`npm run typecheck`、`npm run build`、`npm run test:e2e` 全部通过；本地预览文件在正式发布前移除，不进入公开构建产物。

## 非目标

- 不修改题库内容、路线卡片顺序、密码和解锁机制。
- 不增加账号、云同步、服务端或第三方 UI 框架。
- 不把技术资料全文复制到左侧或中央，避免同一内容重复展示。
