# 面试卡片多设备响应式布局设计

## 目标

让同一套面试卡片 PWA 在手机、平板、桌面网页上都保持清晰的阅读层级、稳定的学习操作和足够的内容利用率，不改变解锁、题库、进度和加密逻辑。

## 现状判断

- 当前样式以手机为基准，只有 `700px` 和 `380px` 两个断点。
- 桌面仍使用固定在底部的移动端导航，主内容最大宽度为 960px，学习卡片最大宽度为 760px。
- 首页、浏览页和学习页没有针对宽屏建立布局层级；大屏会出现空白，学习页无法同时利用题目区和回答区。
- 现有测试覆盖移动端和不横向溢出，但没有验证平板、桌面导航模式和学习页宽屏分栏。

## 设计原则

1. 保留一套 React DOM，通过 CSS 媒体查询切换布局，不在 JavaScript 中监听窗口宽度。
2. 断点采用 `768px` 和 `1200px`：手机 `320–767px`、平板 `768–1199px`、桌面 `>=1200px`。
3. 页面外框可变宽，正文阅读行宽受限在约 70–80 个中文字符，避免桌面长行难读。
4. 所有触控目标继续保持至少 44px，安全区、键盘焦点和减少动画设置不回退。
5. 学习流程优先于装饰：手机/平板保持题目到回答的纵向顺序，桌面才启用左右分栏。

## 布局方案

### 手机

- 单列内容，页面边距 16px。
- 底部导航固定，应用内容为导航预留安全区。
- 学习页题目、回答和评分栏纵向排列；回答区默认折叠保持不变。

### 平板

- 页面内容最大宽度 1120px，边距随视口增加。
- 导航从底部浮层变成页面顶部横向导航，避免占用阅读底部空间。
- 首页指标和题库入口使用两列；浏览筛选项横向排列。
- 学习页仍为单列，回答宽度扩大但不强制分栏。

### 桌面

- 应用外壳使用左侧固定导航，主内容区最大宽度约 1180px。
- 首页使用“主要复习内容 + 薄弱分类”双栏布局。
- 浏览页使用双列题目摘要；展开的卡片跨列显示完整回答。
- 学习页使用左右分栏：左侧题目和计时保持可见，右侧显示 30 秒回答及可展开内容；评分栏仍固定在视口底部并保持宽触控目标。

## 结构调整

- `App.tsx` 将内容包裹为 `app-content`，导航统一命名为 `main-nav`；不复制三套导航。
- `Dashboard.tsx` 为题库区域增加语义 class，支持桌面网格排布。
- `StudyScreen.tsx` 将问题卡与回答面板放入 `study-layout`，移动端仍按视觉顺序纵向显示。
- `ProgressiveAnswer`、密码解锁、进度和卡片数据接口不变。

## 验收标准

- 在 `320×800`、`390×844`、`768×1024`、`1024×1366`、`1280×800`、`1440×900` 下没有横向滚动。
- 手机显示底部导航；平板显示顶部导航；桌面显示左侧导航。
- 桌面学习页回答区与题目区并排，移动端仍为纵向流程。
- 题目、回答、追问折叠、评分按钮和键盘操作行为与改造前一致。
- Node 24 下单元测试、类型检查、生产构建和 Chromium/WebKit E2E 通过。

## 非目标

- 不改变密码、加密信封、题库内容、学习调度或 IndexedDB 数据格式。
- 不新增第三方字体、组件库或远程资源。
- 不在本轮直接发布到 GitHub Pages。
